## Архітектура бота

### Режими
- **Звичайний** — клієнт, відповідає як асистент
- **Адмін** (`/admin`) — Влад, може навчати бота через діалог, бачить додаткові команди. Відповіді однакові як для клієнта, але додатково: LEARN зберігає факти, фото прикріплюється до останнього KB запису

### GPT формат відповіді
```
REASON|||причина
START_ORDER (якщо треба запустити анкету)
PHOTO_REQUEST|||тип або all
Текст відповіді клієнту
```
Мітки парсяться і видаляються перед відправкою клієнту.

### Анкета замовлення
8 кроків: тип -> плетіння -> довжина -> маса -> покриття -> застібка -> додатково -> контакт
- Довжина динамічна: ланцюжок 40-75см, браслет 18-25см
- Маса — вільний ввід (без кнопок)
- Кожен крок має кнопку "Назад"
- Адмін `/neworder` додає крок "Звідки клієнт?" на початку

### База знань (knowledge_base.json)
Структура запису:
```json
{
  "id": "kb_001",
  "trigger": "як виміряти руку",
  "response_text": "...",
  "media": [{"type": "photo", "path": "channel_photos/..."}],
  "tags": [],
  "created": "09.03.2026",
  "source": "admin_learn"
}
```
Пошук через GPT — порівнює запит з тригерами всіх записів.
